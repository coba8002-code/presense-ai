# 개 영상 평가 계약 v1

## 구현 범위
P0: 실제 정답 파일을 만들기 전에 고정하는 평가 단위와 검증 CLI다. 모델 실행·학습·방송 수집·실제 개 행동 성능 측정은 하지 않는다. 코드: `evaluation/video_contract.py`. 기존 `training.video_review`는 VLM 관찰에서 검수 후보를 만든다. 그 후보는 모델 출력을 본 뒤 작성될 수 있으므로 **독립 평가 정답으로 자동 변환하지 않는다**.

## 평가 단위와 라벨
한 단위는 특정 개 한 마리의 로컬 원본에서 잘라 해석하는 반개구간 `[start_seconds,end_seconds)`이다. 최소0.1초, 원본 최대600초. `subject_reference`로 다견 영상에서 대상 개를 지목한다. 평가 입력에는 원본 해설·자막의 정답 노출을 제거한 대상 구간만 사용해야 하며 실제 입력 생성은 후속이다.

|정답|관찰 기준|
|---|---|
|standing|몸통을 바닥에 눕히지 않고 다리로 지지하며 서 있는 자세|
|sitting|엉덩이를 내려 지지하는 앉은 자세|
|lying|몸통이 바닥에 지지된 누운 자세|
|walking|대상 개가 연속적인 발걸음으로 이동하는 구간|
|unknown|가림·화면 밖·모호한 전이·범위 밖 행동 등 네 라벨로 확정할 수 없음|

위 기준은 관찰 주석의 시작점이며 감정·공격성·질환·행동 원인의 정답이 아니다. 검수자는 안정적인 관찰 구간을 고르고 자세 전이나 혼합 동작은 구간을 나누거나 unknown으로 남긴다. unknown에는 occluded/offscreen/ambiguous/out_of_scope 중 이유를 기록한다. 검수 매뉴얼과 실제 사례의 일치도는 전문가 파일럿에서 조정한다. 기준을 바꾸면 계약 버전과 정답 지문도 갱신한다.

## 정답 계약
형식 예제: `docs/examples/video-evaluation/reference.synthetic.json`. 모두 가상 ID·가상 검수자·가상 지문이며 영상 파일은 존재하지 않는다. 실제 자료의 수령·권한·정답 근거가 아니다.

각 행에 clip_id, dataset, dog, 전역 animal_id/household_id/session_id/source_id, 대상 설명, 로컬 상대 경로, SHA256, 원본 길이, 시작/끝 초, split, label과 reviews를 둔다. URL은 로컬 미디어 대신 입력할 수 없다. 개인 이름·연락처를 ID에 쓰지 않고 가명화한 전역 ID로 여러 데이터셋의 동일 개체를 연결한다. unknown/pending ID는 거절한다.

하나의 원본에서 여러 비중첩 구간을 만들 수 있다. 같은 개·같은 파일의 중첩 구간은 거절하고 경계만 맞닿은 구간은 허용한다. 원본 ID의 지문/길이/세션/가정 불일치도 거절한다. 개체·가정·세션·원본·파일 내용 중 어느 하나라도 train/validation/test를 넘으면 거절한다. 최소5마리와 세 분할을 요구하지만 최소 조건 충족은 통계적으로 충분한 표본 수를 의미하지 않는다. 해시로 찾을 수 없는 재인코딩/유사 영상 중복 검사는 후속이다.

각 정답에는 모델 출력을 보지 않았다는 명시적 false, 검수자, 근거, 시각이 필요하다. 일부 표본에는 두 명의 독립 검수를 기록한다. 최종 라벨과 검수 라벨이 다르면 두 검수와 조정 근거가 모두 있어야 한다. 검수 시각은 locked_at 이하여야 하고 잠금은 미래일 수 없다. 문서/정책의 정규화 SHA256을 결과에 남긴다. CLI가 인간의 전문성·실제 블라인드 검수·동일 개체 매핑을 증명하는 것은 아니며 운영자가 원증거를 따로 확인해야 한다. v1은 이중 검수 비율을 강제하지 않으므로 실제 파일럿에서 사전 비율과 표본 추출법을 고정한다.

## 권한과 파일 확인
기존 `training.data.approve_dataset` 레지스트리를 재사용한다. approved·상업/학습 허락·출처/버전/라이선스/권리 근거/동의/검수 기록과 별도 media_acquisition_allowed가 필요하다. 기존 프로젝트보다 느슨한 평가 전용 우회 경로를 만들지 않는다. 레지스트리의 synthetic 여부와 정답 계약의 synthetic 여부가 일치해야 한다. 예제 레지스트리는 가상 메타데이터만 승인하며 외부 방송이나 실자료를 승인하지 않는다.

`--media-root`를 지정하면 허용 루트 안의 파일인지와 SHA256만 검사한다. 파일을 디코드하거나 길이/프레임/대상 개를 확인하는 기능은 아니다. 이 검사가 성공해도 evaluation_ready는 false다. 실제 평가 전에 허가된 원본 수령, 디코딩, 프레임·시간 정렬과 전문가 검수를 확인해야 한다. 이전 학습용 검수 결과를 독립 평가 근거로 재사용하지 않는다.

## 재현 명령
프로젝트 루트의 기본 서버 환경에서 네트워크·API 키 없이 실행한다.
```
python -m evaluation.video_contract \
  --manifest docs/examples/video-evaluation/reference.synthetic.json \
  --registry docs/examples/video-evaluation/registry.synthetic.json \
  --output artifacts/video-contract-synthetic.json
```
실자료는 GitHub 밖의 비공개 경로에 보관하고 `--manifest`, `--registry`, 선택적 `--media-root`에 해당 로컬 경로를 전달한다. 출력은 원본 정답/ID 없이 개수·지문·검증 범위만 남긴다. 기존 출력은 덮어쓰지 않는다. 잘못된 입력은 원본 주석을 로그로 출력하지 않는다.

## 예측 매칭과 후속 지표
v1은 고정 정답 구간 분류다. 예측은 **clip_id + 원본 SHA256 + 동일 시작/끝 초**로 정확히 하나를 대응시키며 누락/실패를 유보로 남긴다. 시각 허용오차·최대 IoU 매칭으로 정답 창을 바꾸지 않는다. 연속 사건 탐지는 별도 버전에서 시간 IoU와 일대일 매칭 계약을 정한다.

P2/P3 후속: 모델/프롬프트/설정/시간/비용/정답 지문을 묶은 예측 파일, 중복·누락 검사, 네 행동의 macro F1·혼동행렬, unknown 정답의 유보율, coverage/선택 정확도, 개체/가정 단위 신뢰구간, 실패 포함 p50/p95. unknown 정답은 맞힌 행동으로 보상하지 않고 판독 불가 범주로 따로 보고한다. validation에서 정한 설정을 잠근 뒤 test를 반복 튜닝에 쓰지 않는다. audio/vision/fusion은 동일 개체·동기화 구간·가용 모달리티 조건으로 비교하며 현재 음향 사건 점수를 자세 정답으로 직접 평가하지 않는다.

## 완료 증거와 남은 조건
분할 누출5종·시간/중첩·잘못된 종·권한/합성 혼합·블라인드/시각/이중 검수·실파일 지문 변경·요약 CLI 비공개 로그를 회귀 검사한다. 이 구현은 형식 계약 단계다. 실제 정답 수집, 전문가 이중 검수, 디코딩/정렬, 예측 실행과 독립 지표는 아직 완료하지 않았다.
