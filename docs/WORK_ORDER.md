## 현재 상태와 승인 범위

기존 ZIP은 제공되지 않았다. 현재 코드는 이전 소스 복원이 아닌 신규 구성이다.
FastAPI, NumPy 오디오 베이스라인, VLM 어댑터가 있으며 로컬 테스트 22개를 통과했다.
실제 데이터 학습, PyTorch 모델, Flutter 앱, 유료 VLM 호출은 완료되지 않았다.

사용자는 상업용 학습 의향과 개발·PR 작성을 승인했다. 이 승인은 외부 데이터의
저작권·라이선스·플랫폼 이용 권한을 대신하지 않는다. 권한이 불명확한 데이터는
학습하지 않는다. 유료 API·GPU 사용, 배포, PR 병합은 이 작업의 승인 범위에 없다.

## 실행 순서

`WO-01 환경/CI → WO-02 데이터 사전 점검 → WO-03 권한/데이터 확보 → WO-04 실제 오디오 학습`

`WO-05 VLM 검증 → WO-06 결합 평가 → WO-07 기록/개인정보 → WO-08 Flutter → WO-09 출시 검증`

WO-02의 코드와 합성 데이터 검증, WO-05의 오프라인 오류 검증은 외부 설치가
막혀 있어도 진행한다. 선행 조건이 없는 작업을 임의로 완료 처리하지 않는다.

## WO-01 — 실행 환경과 CI

- 작업: Python 3.12 격리 환경에서 requirements.lock 설치, 의존성 검사,
  테스트 및 서버 상태 확인. 실행 환경 진단 도구를 만들어 누락 패키지와 도구를 보고한다.
- 작업: PR 변경 시 CI가 실행되는지 확인하고 필요하면 브랜치 push/수동 실행 진입점을 보완한다.
- 완료 기준: 깨끗한 환경의 설치 로그, 전체 테스트 성공, `/healthz` HTTP 200,
  의존성 취약점 검토 결과와 해당 커밋의 성공 CI 링크.
- 현 차단: 셸 네트워크 권한 요청이 대기 후 중단됨. 추가 요청을 반복하지 않고
  GitHub 커넥터와 오프라인 검증을 사용한다. 설치 성공이나 CI 성공으로 간주하지 않는다.
- 담당: 개발 에이전트; 환경 권한/구성 변경은 소유자.

## WO-02 — 학습 전 데이터 검사 [이번 실행의 코드 작업]

- 작업: `python -m training.preflight`를 추가한다. 학습 없이 레지스트리 권한,
  manifest 형식, 상대 경로, 파일 무결성, 음원 형식, 개체 분리와 클래스 분포를 점검한다.
- 작업: 잘못된 JSON 구조, 모호한 개체 ID, 절대 경로, 권한 누락은 명확한 오류로 중단한다.
- 산출물: 사전 검사 CLI, 구조화된 요약, 회귀 테스트, README 실행 예시.
- 완료 기준: 합성 dog/cat 입력 성공, 미승인 자료는 음원 읽기 이전에 실패,
  손상 WAV·경로 이탈·개체 누락·검증 세트 클래스 누락 실패. 실패 시 종료 코드 2.
- 주의: 통과는 자료의 법적 권한이나 라벨의 진실성을 자동으로 입증하지 않는다.

## WO-03 — 권한 확보와 자료 반입

- Barkopedia: 정확한 하위 데이터셋/버전 선택, 원본 미디어 및 플랫폼 권한 확인.
- CatMeows/Meow-Net: 상업용 사용 허가 또는 상업용으로 사용 가능한 대체 자료 확보.
- AP-10K: 버전·출처·표시 의무·개체 분리 가능성 확인.
- Animal Kingdom: 접근 조건·상업용 및 원본 미디어 권한 확인.
- 산출물: 증거 링크/허가 문서 위치, 버전, 동의 근거, 검토자/날짜가 포함된 registry 변경 PR.
- 완료 기준: 소유자 의향 승인과 외부 권한을 별도로 기록하고 승인된 자료만 반입한다.
- 담당: 소유자가 보유 자료/허가를 제공; 에이전트가 메타데이터와 검사 절차 구현.
- 이전 ZIP 확보 시: 별도 디렉터리에서 검사하고 현재 코드와 비교한다. 내용을 추정하거나 덮어쓰지 않는다.

## WO-04 — 실제 오디오 학습과 PyTorch 비교

- 선행: WO-01~03 완료, 알려진 전역 개체 ID와 관찰 근거가 있는 라벨.
- 작업: 승인 자료의 변환 기록을 남기며 16 kHz PCM WAV로 전처리하고
  사전 검사를 통과시킨다. 학습/검증/시험 개체를 고정한다.
- 작업: 현재 NumPy 기준 모델과 PyTorch 모델을 동일 시험 세트로 비교한다.
- 완료 기준: 모델·코드·환경·데이터 버전, 분할과 seed, accuracy/macro F1,
  confusion matrix, 클래스별 표본 수, calibration/abstention, 실패 사례 및 모델 카드.
- 금지: 합성 음원 성능을 실제 동물 행동 성능으로 보고하거나 시험 세트로 모델 선택.

## WO-05 — VLM 통합 검증

- 선행: 실제 호출은 별도 비용 승인, 제공자 설정, 이미지 공유 동의 및 적법한 자료.
- 작업: 관찰(자세/귀/꼬리)과 가설을 분리하고 불확실성·판단 보류를 일관되게 처리한다.
- 완료 기준: 스키마·입력 크기·동의·인증·거절·timeout·잘못된 응답 회귀 테스트,
  승인 후 실제 모델 호환성 및 사람이 라벨링한 이미지 평가 결과.
- 금지: API 키/이미지 로그 보관, 문자 그대로의 동물 언어 번역, 수의학적 진단 주장.

## WO-06 — 오디오/영상/맥락 결합

- 선행: WO-04~05와 동기화된 동일 개체의 멀티모달 평가 자료.
- 작업: audio-only, vision-only, fusion을 같은 holdout과 라벨로 비교한다.
- 완료 기준: 누락 모달리티/상충 증거 처리, 비교 지표와 오차 분석,
  결합이 개선되지 않으면 그 결과를 그대로 기록한다.

## WO-07 — 반려동물 기억·피드백·개인정보

- 작업: 사용자/반려동물 소유권 모델, 보관 기간, 기록/피드백, 내보내기/삭제 설계 및 구현.
- 완료 기준: 다른 사용자 자료 접근 차단, 보관 만료/삭제 검증,
  최소 수집과 동의 철회에 따른 동작, 원본 미디어의 기본 비보관.
- 의존: 운영 인증/저장소 선택을 문서화하고 개인정보를 합성 테스트 데이터로 검증.

## WO-08 — Flutter 앱

- 선행: Flutter SDK와 플랫폼 빌드 도구, 안정된 백엔드 계약.
- 작업: 녹음/영상 입력 → 공유 동의 → 분석 → 불확실성 포함 결과 → 기록 화면.
- 완료 기준: 권한 거절·네트워크 오류·판단 보류 UI 테스트, Android/iOS 재현 빌드.
- 금지: 공유 서버 토큰 또는 제공자 API 키를 앱에 내장.

## WO-09 — 운영 보안과 최종 검증

- 작업: 사용자별 인증/인가, 공용 요청 제한, 업로드 제한,
  비밀 관리, 보관/삭제 정책, 장애 처리, 실제 기기 QA.
- 완료 기준: CI/취약점 검사/모바일 빌드 증거, 데이터 및 모델 카드, 미해결 위험 목록.
- 배포/병합은 검토 가능한 결과를 제시한 후 별도 지시를 따른다.

## 공통 검증 명령과 보고 규칙

```sh
python scripts/verify_skills.py
python scripts/check_environment.py
python -m unittest discover -s tests -v
python -m compileall -q backend training evaluation scripts
```

실행하지 않은 검사는 `미검증`, 외부 선행 조건 때문에 진행할 수 없으면 `차단`으로 기록한다.
매 변경마다 실제 통과 테스트 수와 새 실패 원인을 갱신하고 PR에 반영한다.
실패 테스트를 삭제하거나 권한 게이트를 풀어 완료 상태를 만들지 않는다.
