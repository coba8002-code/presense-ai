# 개체·견종·체형·상황 정보 적용

2026-11-01. 개 전용. 견종은 선택 보조 정보이며 모름/믹스를 지원한다. 견종별 별도 모델을 만들거나 견종으로 성격·감정·공격성을 단정하지 않는다. [Battersea](https://www.battersea.org.uk/pet-advice/dog-advice/understanding-your-dogs-body-language)와 [Dogs Trust](https://www.dogstrust.org.uk/dog-advice/understanding-your-dog/body-language)의 형태·개체·맥락을 함께 확인하는 원칙을 참고했다. 이 문서를 검증된 감정 라벨로 사용하지 않는다.

## 실제 제품 흐름

1. `/app`에서 로그인/계정 연결 → 프로필의 ‘선택 정보·견종·나이·체형’을 펼친다. 나이(개월), 체중, 견종(모름/믹스/보호자가 알고 있음), 선택 견종명, 귀/꼬리/주둥이 형태와 털 길이를 입력한다. 모르는 수치는 빈칸/null이며 0으로 채우지 않는다. 나이·체중은 입력 당시 보호자 보고이고 자동 갱신/사진 추정이 아니다.
2. 프로필 보관 동의 후 등록/수정한다. 서버가 guardian_report/verified=false/reported_at을 붙인다. 클라이언트는 검증됨·자동 견종 추정·AI 결과를 입력할 수 없다. 기존 이름만 있는 프로필은 details=null로 보존한다.
3. 분석 당시 상황을 선택 입력한다: 혼자/놀이/산책/식사/휴식/낯선 사람·개/모름, 주변 개 수, 발성 개체를 보호자가 확인했는지, 마이크 기기 별명/거리/잡음, 함께 촬영한 영상의 몸 가시성. 기기 별명은 개인정보 없는 40자 이하 코드이며 영상 없음/모름도 허용한다. 영상 파일을 업로드하거나 가시성을 자동 확인하는 기능은 아니다.
4. 별도 ‘상황과 저장된 프로필 정보 보관’ 동의가 있을 때만 소리 작업에 맥락을 연결한다. 원본 소리는 기존 임시 보관 규칙을 따르고 맥락/당시 프로필은 결과와 함께 등록부터 최대24시간, 프로필이 먼저 만료되면 그때까지다. 미저장 프로필 편집값을 작업에 임의로 붙이지 않는다.
5. 결과에서 보호자 보고를 모델 점수와 분리해 보여준다. 여러 마리·발성 개체 미확인·가림이면 관련 해석을 보류한다. 꼬리 없음은 꼬리 신호 해석 제외, 짧거나 말린 꼬리는 개체의 평소 중립 모양 비교 필요, 처진 귀는 귀 밑부분 가시성 확인, 긴 털은 가림 확인을 안내한다. 이는 보호자 입력을 바탕으로 한 질문/제한이며 실제 영상 관찰 결과나 성능 보정 완료가 아니다.

현재 AST는 음원만 받는다. 맥락/프로필은 작업자 claim·모델 프롬프트·외부 제공자에 전달하지 않으며 점수를 변경하지 않는다. model_conditioning=false, training_approved=false다. 견종 정보와 몸 형태로 실제 VLM 추론·정확도가 향상됐다는 주장은 하지 않는다. 기존 개체별 모델 점수 기준선은 같은 개/모델/기기/조건/출처를 나누는 방식 그대로 유지한다.

## 계약·저장·삭제

- `POST /v1/me/pets`, `PATCH /v1/me/pets/{id}`의 선택 필드 `details`: breed_kind, breed_name, age_months(0..360|null), weight_kg(0.1..200|null), ears, tail, muzzle, coat. species=dog는 기존과 같다. 이름만 수정하면 기존 details를 보존하고 명시적 details=null은 현재 정보를 모름으로 바꾼다.
- `POST /v1/me/audio-jobs`는 선택 `X-PetSense-Context` JSON(2KB 이내)와 `X-Context-Storage-Consent: guardian-context-v1`를 함께 받는다. 동의 없이 맥락을 제출하면403. 잘못된 값/검증 주장/감정 라벨은422. 맥락이 없으면 기존 요청과 동작을 유지한다.
- 맥락은 접수 트랜잭션에서 당시 저장 프로필과 함께 불변 스냅샷으로 연결한다. 같은 접수 키로 맥락을 바꾸면409, 같은 요청은 재사용한다. 프로필을 나중에 수정해도 이전 스냅샷을 새 정보로 덮어쓰지 않는다. 예전 작업 정보까지 지우려면 해당 작업을 취소·삭제하거나 프로필 전체를 삭제한다.
- 다른 계정은 프로필/작업 맥락을 조회할 수 없다. 세션 변경은 화면 입력·표시·전송을 초기화한다. 맥락/동의 변경은 진행 중 브라우저 요청을 중단하지만 이미 서버에 접수됐는지는 목록 조회 후 취소·삭제로 확인해야 한다.
- 작업 취소·만료/철회·프로필 삭제/만료·회원탈퇴/보관기한 만료 시 연결 맥락을 삭제한다. 프로필 상세는 부모 프로필 수명을 따른다. 별도 가족 공유나 상담 리포트에 새로운 상세 필드를 자동으로 추가하지 않는다.
- 스키마 v8→v9는 기존 테이블을 바꾸지 않고 pet_details/job_contexts 테이블만 추가한다. 기존 프로필·일지·작업·관찰을 보존하며 기존 음원만 있는 작업의 접수 키 계산은 유지한다. 새 테이블도 독립 개인정보 만료 정리에서 처리한다.

## 구현 범위와 남은 검증

| 항목 | 상태 |
|---|---|
| 선택 프로필/API/UI·모름/믹스·입력 출처 | 구현 |
| 분석 당시 상황·별도 동의·당시 프로필 연결 | 구현 |
| 개체/상황/형태에 따른 추가 질문·해석 제한 | 구현, 미검증 규칙 |
| 기존 같은 개의 점수 기준선 | 재사용, 실제 장기 개인화 미검증 |
| 견종/체형을 반영한 모델 보정 | 미실행, 현재 AST 점수에 미반영 |
| 견종·체형별 정확도/공정성 비교 | 실제 독립 정답·개체/가정/원본 분리가 필요 |
| 실제 휴대폰/국내 PC 운영 | 미검증, 브라우저 모바일 에뮬레이션과 구분 |

개발/검증 순서는 공통 소리·영상 분석 → 개체별 장기 기준선 → 체형별 관찰 가능성/모델 보정 → 표본을 갖춘 견종별 검증이다. 프로필을 입력한 것만으로 개체·가정 독립 학습 정답을 확보한 것이 아니다. 개인 프로필/상황/피드백을 별도 학습 동의·권리/검수/분할 없이 데이터셋으로 내보내거나 자동 학습하지 않는다. 실제 데이터가 없으면 견종별 성능 수치를 만들지 않는다.

로컬/원격 검사는 미검증 신뢰 주장·잘못된 수치·다른 계정 접근 거부, v8 마이그레이션, 과거 정보 보존/접수 재사용·충돌, 작업자 메타데이터 미전달, 삭제/기한, 실제 브라우저 프로필 편집→작업→별도 작업자→결과→삭제/계정 전환을 포함한다. 음원/신원은 테스트용이며 실제 견종/행동 성능 증거가 아니다.
