# 계정별 비동기 소리 분석 작업

## 현재 구현
단일 국내 PC용 SQLite 큐와 별도 AST 작업자다. HTTP 접수/상태 조회와 실제 계산을 분리하고 프로세스가 재시작해도 대기 상태를 보존한다. 운영 회원가입·분산 큐·OS 자원 샌드박스·클라우드 배포·실제 개 행동 성능을 완성한 것은 아니다. AST 원본7라벨과 abstain 계약을 유지하며 모델을 추가 학습하지 않는다.

## 실행과 모드
같은 서버/모델 가상환경에 기존 requirements와 선택적 AST 의존성을 설치하고 공개 고정 가중치를 명시적으로 캐시한다. API와 worker가 같은 비공개 DB와 HF_HOME을 사용해야 한다. 환경변수 PETSENSE_ACCOUNT_DB와 PETSENSE_ENABLE_AST_JOBS=true를 설정한다. .env.example은 자동으로 로드되지 않는다.
```
python -m scripts.cache_audio_model --cache-dir data/model-cache
python -m uvicorn backend.app:app --host 127.0.0.1 --port 8000
python -m backend.job_worker --db data/private/notes.sqlite3 --watch
```
HF_HOME은 준비한 캐시의 절대 경로로 설정한다. 마지막 명령은 별도 터미널/서비스에서 실행한다. --watch 없이 실행하면 최대 한 작업만 처리한다. 작업자를 띄우지 않아도 접수할 수 있지만 처리되지 않으며15분 후 만료된다. 서버/작업자 둘 다 멈춘 디스크를 자동 삭제하는 기능은 아니다. [독립 정리 CLI](PRIVACY_MAINTENANCE.md)를 별도로 실행할 수 있으며 실제 PC 서비스 등록·모니터링·백업 삭제 검증은 별도다.
큐 활성화 중에는 /v1/audio/events 직접 AST 추론을503으로 막아 같은 서버 모드에서 병렬 모델 경로가 생기지 않게 한다. 기본false에서는 기존 요청별 직접 분석을 유지한다. /v1/audio/chunks의 작은 기존 실시간 경로와 큐를 모델 성능으로 혼동하지 않는다.

## 사용자 흐름과 명시적 동의
계정 세션·반려견 프로필을 준비하고 /app에서 소리 파일/최대10초 녹음 구간을 선택한다. 분석 동의 외에 **큐 처리용 소리 임시 보관 동의**를 별도로 체크하고 ‘선택한 소리 작업으로 분석’을 누른다. 브라우저는 최대10초·16kHz PCM16 WAV로 변환해 한 번 접수한다. 새 접수에는 새 UUID 멱등 키를 쓴다. 전송 결과가 불명확하면 자동 재등록하지 않고 작업 목록을 먼저 확인한다.
상태는 대기/분석/완료/실패/취소/만료다. 최대60회 자동 조회 후 수동 조회할 수 있고, 완료 점수는 감정·원인의 확정 판단이 아니다. 작업 취소·결과 삭제는 원본/결과를 제거한다. 화면 이탈이나 동의 체크 해제는 이미 접수된 작업의 취소가 아니며 목록에서 따로 취소한다. 브라우저 저장소에 원본·세션·작업 결과를 자동 저장하지 않는다. 기존 직접 분석의 취소 동작과 구분한다.

## 저장·삭제 계약
- 16kHz PCM16 WAV0.1~10초·최대2MB·업로드15초. 원본은 작업 등록부터최대15분을 목표 TTL로 DB BLOB에 보관하며 성공/실패/취소 시 더 일찍 제거한다. 작업자와 조회/정리 경로가 실행돼야 물리 DB 정리가 진행된다.
- 결과와 최소 작업/멱등 메타데이터는 등록부터최대24시간. 취소 시 원본/결과는 즉시 제거하고 재시도 중복 방지용 최소 행은24시간까지 남긴다. TTL 이후 동일 멱등 키의 재사용은 새 등록이 될 수 있다.
- 프로필 만료/삭제와 계정 삭제는 해당 작업 행까지 제거한다. 계정 삭제는 사용량 원장도 지운다. 같은 이름의 다른 프로필/다른 계정에는 영향이 없다.
- 생성 세션의 해시만 보존한다. 세션 만료/철회 시 대기·실행 작업을 취소한다. 살아 있는 작업자는0.25초 간격의 상태 확인 후 모델 자식을 종료하며 원본/결과를 반환하지 않는다. 실제 종료 시점은 DB/프로세스 스케줄링에 영향을 받는다.
- 결과에는 training_approved=false. 서버 분석 보관 동의를 학습 동의로 확대하지 않는다. 별도 데이터셋/권리/검수 경로가 필요하다. SQLite는 비공개 경로/파일권한/secure_delete를 쓰지만 백업·스왑·디스크 복구까지 완전 삭제한다고 주장하지 않는다.

## 권한·한도·복구
모든 큐 API는 계정 세션만 받으며 공유 개발 토큰을 인정하지 않는다. 서버가 소유한 pet_id만 접수한다. 세션·프로필·용량·멱등·사용량 검사는 같은 SQLite 쓰기 트랜잭션에서 수행한다. 같은 owner/key/content 재접수는 같은 작업을 반환하고 사용량을 추가하지 않는다. 같은 키의 다른 내용은409다.
한 DB에서 전체 대기/실행8개, 계정당2개, 계정당 UTC일20개 접수. 취소/실패도 사용량으로 남고 멱등 재조회는 추가 과금하지 않는다. 이는 로컬 자원 보호용 고정 개수이며 유료 상품 한도나 비용 추정치가 아니다. 업로드 입구의 기존 메모리 admission은 API 프로세스별이며 운영 전 분산 입구 제한은 별도다.
큐 작업자는 DB에서 전역 실행1개만 점유하고90초 lease를 사용한다. 실제 모델 자식은60초 제한이다. 원본은 stdin으로 전달하고 runtime offline 캐시만 사용한다. 취소/철회/삭제 후 늦게 도착한 결과와 예전 lease 결과는 저장하지 않는다. 강제 종료/lease 만료는 worker_lost 실패로 남고 **자동 재추론하지 않는다**. 대기 작업은 worker 재시작 후 처리한다. SIGTERM/정상 취소는 자식 종료/회수를 시도한다. OS 강제 종료·Windows 후손 프로세스·자원 제한은 별도 운영 검증이 필요하다.

## API
|경로|계약|
|---|---|
|POST /v1/me/audio-jobs|WAV, X-PetSense-Session, X-PetSense-Pet-ID, X-Audio-Species=dog, X-Audio-Consent=true, X-Job-Storage-Consent=true, Idempotency-Key16~128자.202 상태 반환|
|GET /v1/me/audio-jobs|내 최근20개, 원본/세션/멱등 키 원문은 미반환|
|GET /v1/me/audio-jobs/{id}|내 상태/완료 결과. 다른 계정/없는 ID 모두404|
|DELETE /v1/me/audio-jobs/{id}|X-Delete-Confirm=cancel-job. 실행 취소 또는 완료 결과 삭제|

미설정503, 인증401, 동의403, 형식415/422, 크기413, 업로드408, 한도429, 키 충돌409. no-store 응답. DB 스키마v3는 v1/v2의 계정/프로필/메모를 보존하고 jobs/usage 테이블을 추가한다.
