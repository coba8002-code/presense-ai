# 상황별 돌봄·관찰 계획 — 2026-10-31

목적: 보호자가 상황 일지에 자신의 관찰 목표와 예정 시각을 정하고 후속 기록으로 돌아오게 한다. 자동 훈련 처방·알림 전송·의학적 효과 검증은 하지 않는다. 소유자만 작성/완료/취소/삭제하며 viewer에게 새 권한을 부여하지 않는다.

계획은 한 상황에 연결된다. 목표 1~200자, 기한은 서버 현재부터30일 이내이며 상황 만료보다 빨라야 한다. 계획 보관은 min(생성+30일, 상황 만료). 별도 동의 care-plan-storage-v1, 생성 멱등 키16~128자. 상황당10개·계정당100개 보관 상한. 목표/기한 수정은 초기 범위에서 제외하고 취소 후 새 계획을 만든다. 상태 planned/completed/cancelled. 완료는 같은 소유자/상황의 후속 기록 ID와 보호자의 명시적 확인이 필요하다. 후속은 계획 생성 이후 저장되었고 관찰 시각이 미래가 아니어야 한다. 이는 보호자의 완료 진술이며 수행 사실·교정 효과의 독립 증거가 아니다. 같은 완료 재시도는 같은 결과, 다른 완료/취소 상태 충돌은409. 취소·완료로 TTL을 늘리지 않는다.

API /v1/me/care-plans GET(case_id)/POST, /{id} PATCH/DELETE. SQLite v6→v7. 만료/상황·반려견·계정 삭제에 연쇄 삭제, 독립 정리에도 포함. 목록은 선택 상황 최대10개. 완료 후 후속 기록은 해당 상황 삭제 시 함께 제거된다. 서버에서 알림을 발송하지 않고 기한 경과는 화면에서 상태와 별도로 표시한다.

UI: 기존 상황 상세 아래 한국어/영어 목표·기한·보관 동의, 계획 목록, 연결할 후속 선택·완료/취소/삭제. 선택 상황/프로필/계정/페이지 변경 시 입력과 비동기 응답 초기화. 후속 저장 후 다시 상황을 열면 계획/후속 목록 갱신. 기존 상담 리포트에는 이 버전에서 계획을 포함하지 않으며 상황·후속만 담는 기존 범위를 유지한다.

검증: 멱등/한도/기한/실패 후 무변경/타계정·다른 상황·미래 후속 차단/상태충돌/삭제·TTL/마이그레이션/CSRF 및 실제 HTTPS 계획 생성→후속→완료→삭제. 순서: 실패 테스트→저장·API→화면→회귀 검사→PR. 신규 의존성 없음. `python -m unittest discover -s tests -p test_care_plans.py -v`; `python scripts/verify_release.py --output <new-file>`.
