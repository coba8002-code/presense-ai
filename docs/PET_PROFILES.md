# 반려견 프로필·소유권

## 구현 범위
기존 운영자 발급 계정 세션에 개 전용 프로필을 추가한다. 운영 회원가입/소셜로그인/가족 공유를 새로 구현한 것은 아니다. 프로필은 무작위 UUID와 서버의 계정 소유권으로 구분하며 이름이 같아도 별개다. 클라이언트가 owner를 지정하거나 다른 계정의 프로필을 연결할 수 없다.

앱의 ‘계정별 보호자 메모’에서 세션·프로필/메모 보관 동의를 입력한 뒤 프로필을 조회·등록·수정·삭제한다. 선택한 프로필의 이름은 관찰 입력에 채워지고 서버 메모에 pet_id를 연결한다. 관찰 이름을 직접 바꾸면 프로필 선택을 해제한다. 이름만 있는 과거 메모/브라우저 관찰 기록을 이름 일치만으로 자동 귀속시키지 않는다. 로컬 관찰 기록의 계정 동기화나 기존 음성 API의 프로필 소유권 연결은 별도다.

## 보관과 삭제
수집 필드는 이름·개 전용 종·UUID·소유권·등록/수정/만료 시각뿐이다. 사진·위치·생년월일·건강정보를 추가하지 않는다. 세션 원문은 DB/브라우저 저장소에 저장하지 않는다. 프로필과 메모에 별도 서버 보관 동의를 요구한다.
계정당 최대20개. 프로필은 등록/명시적 이름 수정부터30일, 메모는 작성부터30일 보관한다. 단순 조회로 수명을 늘리지 않는다. 프로필 만료/삭제 시 그 ID에 연결된 메모도 삭제한다. 같은 이름의 다른 프로필·이름만 있는 과거 메모는 유지한다. 메모의 이름은 작성 당시 서버 프로필 이름의 스냅샷이므로 프로필을 바꿔도 과거 메모를 덮어쓰지 않는다.
계정 전체 삭제는 해당 계정의 프로필·메모·모든 세션을 삭제한다. 브라우저 기록은 별도다. 만료 정리는 접근 시 실행하는 단일 PC 개발 규칙이며 정기 purge/백업 포함 물리 삭제까지 완료한 것은 아니다.

## API
전부 X-PetSense-Session과 기존 PETSENSE_ACCOUNT_DB를 사용한다. 공유 개발 토큰은 이 경로의 계정 세션을 대신하지 못한다. 성공/실패 응답은 기존 /v1/me/ no-store 정책을 따른다.

|경로|동작|
|---|---|
|GET /v1/me/pets|내 프로필 최대20개|
|POST /v1/me/pets|X-Storage-Consent=true, JSON name과 선택적 species=dog|
|PATCH /v1/me/pets/{id}|같은 동의와 name으로 이름 수정; ID 유지|
|DELETE /v1/me/pets/{id}|X-Delete-Confirm=delete-pet; 연결 메모 삭제|
|POST /v1/me/notes|기존 pet/context와 선택적 pet_id. 연결 시 서버가 실제 이름을 결정|
|GET /v1/me/notes?pet_id={id}|해당 내 프로필의 메모만 조회|

프로필 입력4KB·업로드15초, 이름1~40자, 임의 추가 필드/비개 거절. 없는 프로필과 다른 계정 프로필은 동일404다. 동의403, 세션401, 한도409, 잘못된 입력422, 미설정/DB불가503. 프로필 쓰기는 같은 SQLite 트랜잭션 안에서 세션·소유권을 확인한다.

## 마이그레이션과 검증
user_version1의 notes에 nullable pet_id와 pets/index를 트랜잭션으로 추가해 v2로 올린다. 과거 메모/세션은 보존하고 재실행은 안전하다. 알 수 없는 미래 버전을 낮추거나 덮어쓰지 않는다. 운영 DB는 변경 전 검토된 백업/복구 경로를 준비해야 하며 이 코드가 운영 배포나 실제 PC DB 변경을 수행한 것은 아니다.
회귀 검사: 동일 이름의 서로 다른 ID, 계정 격리·주입/비개/미동의, 이름 스냅샷, 연결 메모만 삭제, 구버전 보존, 계정 삭제·한도·만료·철회·미래 버전. 실제 Chromium 시나리오는 프로필 생성→이름 변경→메모 ID 연결→삭제 및 HTML 문자 안전 표시를 검사한다. 원격 결과는 tasks/todo.md에 기록한다.
