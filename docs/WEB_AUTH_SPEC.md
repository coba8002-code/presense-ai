# 웹 계정 베타 구현 계약

## 목표와 경계
외부 유료 인증 서비스 없이 회원가입→로그인→프로필/메모/분석 작업→로그아웃/복구/탈퇴를 실제 웹 API로 연결한다. 이메일은 계정 식별자로만 사용하며 소유 확인을 했다고 표시하지 않는다. 이메일 확인·소셜 로그인·분실 복구코드의 별도 신원 확인·실제 운영 HTTPS/메일 전송은 별도다. 기본 비활성화한 제한 베타이며 공개 운영 보안 심사나 서비스 출시 완료를 의미하지 않는다.

## 위협 모델
자산은 비밀번호/복구코드/세션, 이메일, 보호자 메모, 음성 작업이다. 신뢰 경계는 HTTPS JSON 입력, 브라우저 쿠키/Origin, 계정 DB, 모델 작업자다. 공격 사례는 이메일/owner 주입, 로그인 추측, 계정 간 데이터 접근, 로그인/수정 CSRF, 세션 고정, 복구코드 재사용, 세션 변경 뒤 늦은 결과 표시, KDF 메모리 고갈, 탈퇴 후 파생 데이터 잔류다.

## 결정
- 표준 hashlib.scrypt N32768/r8/p3, 16바이트 무작위 salt, 32바이트 결과. 비밀번호15~128자/UTF-8최대512바이트. 비밀번호 원문/복구코드/세션을 DB·로그·URL·브라우저 저장소에 남기지 않는다.
- 세션은256비트 무작위이며 DB에는 해시만 기록한다. HttpOnly/Secure/SameSite=Strict/__Host-접두사 쿠키, Path=/, 최대24시간. TLS 예외를 운영 코드에 만들지 않는다.
- 고정 HTTPS origin/Host를 요구한다. 가입/로그인/복구는 같은 Origin의 JSON+전용 요청 헤더, 쿠키로 보호된 변경 요청은 세션에서 파생한 CSRF 헤더까지 검사한다. 세션 원문은 Set-Cookie로만 전달하며 JSON·JavaScript에는 반환하지 않는다. 기존 운영자 발급 헤더 세션과 쿠키가 충돌하면 거절한다.
- DB 기반 IP/계정/전체 고정 창 요청 제한과 KDF 실행 lease를 두고 hash 작업은 최대1개로 제한한다. 비밀번호 작업이 취소되어도 실제 KDF가 끝난 뒤 lease를 해제한다. 이 제어가 공개 서비스의 봇 방어/OS 자원 한도를 대신하지 않는다.
- 가입 시256비트 복구코드를 한 번 표시한다. 복구 시 기존 코드와 모든 세션을 철회하고 새 코드로 회전한다. 비밀번호 변경도 같은 회전을 수행한다. 이메일로 보냈다는 표현을 하지 않는다.
- 탈퇴는 현재 비밀번호 재확인 후 프로필/메모/작업/사용량/계정/모든 세션을 삭제한다. 쿠키 사용자에게 기존 개발용 계정 삭제 경로로 재확인을 우회시키지 않는다.
- 이메일/암호 해시는 탈퇴까지 계정 유지 목적. 익명화했다고 부르지 않는 해시 기반 보안 제한 bucket은 최대24시간 정리 규칙을 둔다. IP는 전달 헤더 대신 실제 연결 peer를 쓰며 운영 reverse proxy 신뢰 설정은 별도다.
- 기존 v3→v4 마이그레이션은 계정/프로필/작업을 보존한다. 기존 CLI owner를 이메일 이름 일치로 자동 귀속하지 않는다.
- 실제 /auth 페이지와 /app 쿠키 연결을 추가하며 /design은 계속 API를 호출하지 않는 시안으로 둔다. 로그인/로그아웃·복구로 세션이 바뀌면 프로필/메모/작업의 이전 요청·표시를 초기화한다.

## 구성과 검증
PETSENSE_ENABLE_WEB_AUTH=true, PETSENSE_PUBLIC_ORIGIN=https://..., 운영자/연락처와 약관·개인정보 버전을 명시해야 활성화한다. 테스트는 가짜 계정과 임시 HTTPS 인증서를 사용한다. 실제 키/비밀번호를 채팅이나 저장소에 넣지 않는다.
서버 검사: 암호/복구/세션 해시, 소유권, CSRF/Origin/Host/TLS, JSON 한도, 버전/동의, 복구 재사용/동시 회전, rate/lease, 탈퇴, 구버전 보존. 브라우저: 실제 가입→쿠키→프로필→음성 작업→로그아웃/새 로그인→복구→탈퇴, 저장소·JSON 응답·JavaScript에 원문 세션 미노출. 모델은 기본 mock/선택적 실제 AST를 별도 기록한다. 운영 메일/소셜·실기기·현장 모델 정확도와 구분한다.
