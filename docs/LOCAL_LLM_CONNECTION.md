# 국내 PC LLM 연결 조사 — 2026-10-31

확인: 프로젝트 소스와 로컬 관련 환경변수 이름, 연결된 클라우드 환경, GitHub의 LM Studio/Ollama 검색에서 연결 주소를 찾지 못했다. 로컬 브라우저 읽기 도구는 현재 연결되어 있지 않다. 이 환경의1234/11434 loopback API는 접근되지 않았지만, 이는 국내 PC의 상태를 검사한 것이 아니다. 이전 사용자 화면의 LM Studio 언급은 설치/서버 준비의 현재 증거가 아니다.

국내 PC에서 기존 프로젝트 Python 환경으로 다음을 실행한다:

```
python -m local_pc.llm_probe --output llm-server-check.json
```

기본 대상은 이 명령이 실행되는 PC의 LM Studio(127.0.0.1:1234/v1), Ollama OpenAI 호환 API(127.0.0.1:11434/v1) 두 곳뿐이다. GET /models만 호출하며 모델 로드·생성·학습·영상 전송·포트 개방·광역 스캔은 하지 않는다. 모델 목록은 최대20개/응답64KB, 요청 타임아웃3초, 리다이렉트는 따라가지 않는다. 키는 읽거나 출력하지 않는다. 서버가 인증을 요구하면 authentication_required로 보고하고 우회하지 않는다.

서버 주소를 이미 알고 있다면 `--base-url http://127.0.0.1:포트/v1`를 사용한다. 비밀번호/토큰을 URL에 넣지 않는다. 모델명에 vision이 있어도 이미지 분석 능력을 검증한 것으로 표시하지 않는다. Text LLM은 상담 문장 정리에 쓸 수 있지만 영상 행동 관찰에는 실제 이미지 입력을 지원하는 VLM과 별도 평가가 필요하다.

결과 JSON의 status/model_ids와 실제 서버의 접속 가능한 주소를 확인한 후 명시적 모델 선택→민감정보 없는 합성 생성→이미지 지원 검증→기존 VisionResult 구조·판단 보류 검사를 연결한다. 이 클라우드에서 국내 PC로 직접 연결하려면 실제 연결 경로가 필요하며127.0.0.1은 서로 다른 머신을 연결하지 않는다. 서버를 인증 없이 인터넷에 공개하는 설정을 자동으로 만들지 않는다.
