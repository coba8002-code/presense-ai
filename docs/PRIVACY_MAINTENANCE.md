# 독립 개인정보 만료 정리

## 구현 범위
`python -m scripts.privacy_maintenance`는 API 요청이나 모델 worker 실행 없이 기존 PetSense DB의 만료 정리를 수행한다. 개 프로필/연결 메모·작업, 세션·작업 원본/결과·사용량·보안 요청 제한/lease의 기존 만료 규칙을 재사용한다. 현재 스키마v7인 기존 DB만 받아 누락/다른/구버전/미래 DB를 새로 만들거나 마이그레이션하지 않는다.

기본은 한 번 실행 후 종료다. 반복 실행은 운영자가 명시적으로 `--watch`를 사용한다. 이 개발 환경에서 국내 PC의 작업 스케줄러나 서비스를 설치·실행한 것은 아니다.

```sh
python -m scripts.privacy_maintenance --db /private/petsense.sqlite3 --status-file /private/maintenance-health.json
python -m scripts.privacy_maintenance --db /private/petsense.sqlite3 --watch --interval 30 --status-file /private/maintenance-health.json
```

Windows에서는 같은 가상환경 Python과 실제 비공개 절대 경로를 사용한다. DB를 사용하는 계정에만 접근을 허용한다. 서비스 관리자는 ‘부팅/복귀 시 시작·실패 후 재시작·중복 실행 방지·최소 권한’을 설정해야 한다. 프로그램이 실행 중이어야 반복 정리가 진행되며 PC가 꺼져 있는 동안 디스크를 지울 수는 없다. 재개 시 첫 정리를 즉시 수행한다.

## 보관·실행과 관측
기본 간격30초(설정5~300초)다. 원본15분/결과24시간/메모·프로필30일은 각 자료의 만료 정책이며 물리 정리는 실행 간격·DB 잠금·OS 스케줄링만큼 늦을 수 있다. 작업 원본은 완료/취소/만료/철회/작업자 유실 때 먼저 제거한다. 만료된 실행 lease의 늦은 결과는 저장하지 못한다. SQLite secure_delete를 적용하지만 백업·스왑·저장장치 복구·OS 강제 종료까지 완전 삭제했다고 주장하지 않는다.

출력/상태 JSON은 UTC 실행 시각·성공/실패·테이블별 남은/삭제된 행 수·제거 원본 개수만 포함한다. 이메일·이름·owner/프로필/작업 ID·세션/복구/암호·미디어·DB 경로를 출력하지 않는다. 집계값도 비공개 운영 정보다. 상태 파일은 임시0600 파일을 원자적으로 교체하며 Windows 접근권한은 운영 설정으로 확인한다. 출력 경로는 DB와 달라야 한다.

상태가 error이면 비공개 DB 접근/스키마/출력 경로를 점검한다. one-shot 실패는 종료 코드1이다. watch는 다음 간격에 재시도한다. 상태 파일 수정이 실패하면 지난 성공 파일이 남을 수 있으므로 **status뿐 아니라 observed_at_utc가 2회 간격+DB 대기5초 이상 오래됐는지** 감시한다. SIGINT/SIGTERM은 다음 실행을 멈추며 현재 트랜잭션의 짧은 처리가 끝날 수 있다. 운영 알림 채널·백업 삭제·장애 복구/롤백 훈련은 별도다.

## 검증
합성 DB 검사: 요청/worker 없는 원본 만료와 새 작업 보존, 반복 실행, 유실 lease/철회 후 결과 차단, 메모/프로필/세션/보안 bucket 만료, 비식별 출력/상태 파일, 누락/다른/구버전/미래 DB 거절. 실제 국내 PC 스케줄러·전원/백업·Windows 자식 프로세스/휴대폰 검증과 구분한다.

G6 care_shares도 만료/개 삭제/양쪽 계정 탈퇴에 따라 제거하며, 독립 정리 보고에 비식별 개수만 포함한다.

care_plans는 최대30일 및 부모 상황 만료 범위로 정리하며, 상황/개/계정 삭제도 계획에 전파한다.
