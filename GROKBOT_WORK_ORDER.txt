3. 기존 인증 세션이 있으면 공식 Google AI Studio(https://aistudio.google.com/)와 Google Cloud Console(https://console.cloud.google.com/)에서 올바른 계정/프로젝트와 기존 API 접근 가능 여부를 확인한다. AX 계정은 필요 없다. 로그인/MFA/동의가 필요하면 해당 PC의 공식 화면에서 사용자에게 처리하도록 요청한다. ChatGPT/Claude/Grok 구독을 Gemini API 권한이라고 취급하지 않는다.
4. 이미 승인된 기존 API 자격증명을 안전한 현지 입력/환경 연결로 적용한다. 새 키 발급·권한 확대·결제/유료 호출·장기 비밀 저장이 필요하면 정확한 대상과 비용/권한을 확인하기 전 실행하지 않는다. 허용 호출 예산이 없으면 링크 분석을 활성화하지 않는다. 작업지시 수신 자체가 데이터 소유자의 이용권을 의미하지 않는다.

6. docs/YOUTUBE_TRAINING.md 순서로 공식 링크 메타데이터/분석→관찰 검토→로컬 원본 검사→프레임 준비를 실행한다. config/knowledge-targeted.example.json의 policies는 비어 있는 예시다. 임의 승인/리뷰어/감정 정답/개체ID를 만들어 넣지 않는다. model inference는 기계 관찰로 기록하고 사람 검토와 분리한다.
7. 프레임을 실제 검토한 사람의 라벨과 가정ID가 준비되면 training.youtube_frames로 frames.json을 내보낸다. 모사 검토를 실제 정답으로 쓰지 않는다. 권리·개체·가정·원본 분리 조건이 충족되면 기존 training.small_vlm로 국내PC의 허용된 로컬 자원에서 작은 실험부터 실행한다. 공유 장비 자원을 독점하거나 유료 GPU를 만들지 않는다. 가중치 자동 배포/병합은 하지 않는다.
8. 실제 정확도/혼동행렬/유보율/처리시간과 실패 사례를 기록한다. 합성 테스트, 사전학습 추론, 실제 가중치 학습, 실제 개 평가를 분리한다. 데이터가 부족하면 기준을 낮추지 말고 정확한 부족 목록을 남기고 다른 독립 작업을 계속한다.
